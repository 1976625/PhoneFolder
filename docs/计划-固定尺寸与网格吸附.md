# 计划：瓦片固定 128px + 桌面图标式网格吸附（v0.10）

> 需求：「瓦片大小调整就不要了，只保留 128 的尺寸」+「像桌面图标位置网格那种能实现吗？」
> 结论：**能实现**，而且不必改窗口技术栈，现有的瓦片拖动（`tile:drag-move/end` + `setPosition`）就够用。

## 1. 现状

- 瓦片尺寸：`tiles[].size` 可在 64–128 之间调，设置页有滑块；窗口尺寸 = `size × (size+20)`，渲染层用 `--tile-size`。
- 拖动位置：`main.js` 的 `tile:drag-move` 里自由跟随鼠标，松手 `tile:drag-end` 写回 `tile.x/y`。
- 当前本机数据：分辨率 1920×1080，任务栏在左 → `workArea = {x:48, y:0, w:1872, h:1080}`；两个瓦片在右侧（x≈1792）。

## 2. 目标

1. **固定 128px**：移除设置里的「瓦片大小」滑块；所有瓦片统一 128（窗口 128×148，含 20px 标签）。
2. **网格吸附**：拖动结束后瓦片落到网格单元格（类似桌面图标），保持对齐、不会出现半格错位的摆放。
3. 保留现有：拖出/排序/重命名/多瓦片/显示桌面可见等行为不变。

## 3. 方案 A（推荐，先做）

### 3.1 网格定义

- 瓦片：128 宽，标签 20 → 占位 128×148。
- 间距：横向 gap 16、纵向 gap 16 → **单元格 144×164**。
- 网格区域：主显示器 `workArea`（自动避开任务栏），四周留 8px。
- 网格原点与列/行数（本机示例）：
  - 原点 `(workArea.x + 8, workArea.y + 8) = (56, 8)`；
  - 列数：`floor((1872 - 16 - 128) / 144) + 1 = 13`，x 范围 56 … 1784；
  - 行数：`floor((1080 - 16 - 148) / 164) + 1 = 6`，y 范围 8 … 828；
  - 最右列瓦片右边缘 1912，仍在 workArea 内（留 8px）；最下行底部 976。
  - 右侧吸附：现在的 x=1792 会吸到最近列 1784，视觉上仍贴右，不会跳到左边。

### 3.2 拖动与吸附

- 拖动中：保持现在的自由跟随，但把边界从 `display.bounds` 改为 `workArea`（不会拖到任务栏下面）。
- 松手时：计算最近单元格 → 若该格已被其它瓦片占用，则按距离从近到远找空位 → 用约 120ms 的小补间动画滑到格子 → 写回配置。
- 与 Windows 桌面图标一致：拖动时跟手，松手才“啪”地落格，不会一格一格跳。

### 3.3 数据与迁移

- `tile.size` 字段保留但固定写 128（旧配置兼容，读入时一律按 128 处理）。
- 配置版本 v4 → **v5** 时：
  - 所有瓦片 `size` 归一为 128；
  - 现有坐标按新网格吸附；两瓦片落同格时依次找空位；
  - 迁移只执行一次。
- 配置示例：`"size": 128` 保留；新增可选 `grid` 配置不必要（先固定规则，不开放自定义间距）。

### 3.4 设置页调整

- 删除「瓦片大小」滑块（以及相关 `size` 输入联动）。
- 在瓦片区/系统区显示一行只读说明：「瓦片尺寸固定 128px」。
- 新增按钮「重新对齐到网格」：立即把所有瓦片整理到网格（同时写配置），方便换分辨率/任务栏位置后修复。

### 3.5 影响文件

- `src/main/main.js`：拖拽边界/吸附计算/补间、`tile:drag-end` 逻辑、启动/迁移后吸附；
- `src/main/services/config.js`：默认 size=128、clamp、v5 迁移；
- `src/main/services/settings.js`：sanitize 强制 size=128、迁移版本；
- `src/main/windows/tile-window.js`：尺寸常量 128；
- `src/renderer/tile/*`：`--tile-size` 固定 128（仍走 payload，不硬编码视觉逻辑）；
- `src/renderer/settings/*`：删除滑块、加只读说明与「重新对齐」按钮；
- 测试：新增网格计算/碰撞单测（纯函数放在新 `services/grid.js`），E2E：拖动松手后坐标是 144/164 的整数格；迁移测试。

### 3.6 验收标准

1. 设置页没有尺寸滑块；新/旧配置所有瓦片都是 128。
2. 拖动任意瓦片松手，位置一定是网格坐标；不会压到任务栏、不会出屏。
3. 两个瓦片不会吸到同一格。
4. 重启后位置保持；换分辨率/任务栏后点「重新对齐到网格」能归位。
5. 现有 E2E（拖出/排序/重命名/设置/开合）全绿，单测全绿。

### 3.7 工作量

0.5–1 天：网格纯函数 + 迁移 ~2h，拖拽吸附/补间 ~2h，设置页与测试/打包 ~2h。

## 4. 方案 B（可选进阶）

「像桌面图标位置网格」如果指的是**严格与 Windows 桌面图标同一网格**（瓦片正好占用某个图标格）：

- 通过 Win32 读取桌面 `SHELLDLL_DefView` 里 `SysListView32` 的 `LVM_GETITEMSPACING`，拿到当前系统图标网格间距（随 DPI/缩放/图标大小变化）；
- 把瓦片吸附点对齐到 Explorer 的图标格；
- 局限：桌面图标本身不占位，仍可能与图标重叠；不同缩放/换分辨率需要重新读取；还需要额外 PowerShell/原生 helper。
- 工作量 1.5–2 天，建议先 A，确认手感后再评估 B。

✅ 方案 A 全部完成，见 [v0.10-进展.md](v0.10-进展.md)：
- 固定 128px、设置页删除尺寸滑块；

- 配置 v4→v5 迁移（尺寸归一 + 坐标吸附）；
- 设置页「重新对齐到网格」；
- 单测 20/20、新增 `scripts/e2e-grid.js` PASS、全部回归 E2E PASS。
