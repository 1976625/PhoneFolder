# v0.9.0 拖出修复 + 桌面层级（2026-10-27）

> 反馈：
> 1. 移进去的软件，拖不出来了；
> 2. 收起状态的瓦片，希望始终在其他软件下面；
> 3. 点击任务栏「显示桌面」，瓦片会随其他软件一起隐藏。

## 1. 拖出修复（真实原因有三层）

排查发现「拖不出来」不是单点问题：

1. **HTML5 dragstart 在 `<button>` 上不可靠**：浮层条目一直是 `<button draggable>`，实测真实鼠标拖拽根本不会稳定触发 `dragstart`；
2. **浮层本身挡住了落点**：浮层是全屏置顶窗口，就算 `startDrag` 成功，鼠标松开时文件也落在浮层自己身上，被判定「已在文件夹内」而跳过；
3. **图标异步导致错过鼠标释放**：原来先 `app.getFileIcon()`（约 1s）再 `startDrag`，等拖拽真正开始时鼠标已经松开了。

**修复**：

- 改用 pointer 事件：条目上按下后移动超过 6px 直接调 Electron 原生 `startDrag`（不再用 HTML5 drag）；
- 拖拽前先把浮层收起（`overlay:close` + hide），让桌面/资源管理器露出来；
- `startDrag` 同步调用，图标用渲染层缓存或应用图标兜底，不再 await；
- 系统拖拽默认是「复制」，拖到桌面后检测到桌面出现同名文件就把源文件删掉，实现「拖出 = 移出」（仅当拖拽前桌面没有同名文件时才删，避免误删）。

**验证**：新增 `scripts/e2e-dragout.js`，用 SendInput 模拟真实鼠标从浮层拖到桌面 → **PASS**（桌面出现文件、收纳文件夹里的源文件消失）。

## 2. 收起状态的瓦片层级

- 常态：通过常驻 PowerShell 调 Win32 `SetWindowPos(HWND_BOTTOM)`，把瓦片压在普通软件的 z-order 之下 → **任何软件窗口都在瓦片上面**；
- 「显示桌面」/ Win+D：轮询前台窗口 + 上一个前台软件窗口是否被最小化 → 判定为显示桌面状态时，瓦片临时置顶（`HWND_TOPMOST`）保持可见；一旦切回软件，自动取消置顶并压回底层；
- 收起浮层后把焦点还给桌面（`focusdesktop`），避免隐藏的浮层窗口一直占着前台，导致层级判断错误；
- 瓦片窗口被系统隐藏/最小化时（500ms 轮询兜底）自动 `showInactive` 恢复。

实现：`src/main/services/native-window.js`（常驻 PowerShell helper，单进程、stdin 命令、约 450ms 轮询一次前台状态）。

**验证**：截图 `shots/crop-z8-showdesktop.png`（显示桌面后瓦片可见）、`shots/crop-z2-covered.png`（软件窗口在前时瓦片在其下面），日志 `desktop state: show-desktop / apps`。

## 3. 已知限制 / 后续

- 桌面前台判定用的是「上一个前台软件是否最小化」的启发式，个别场景（先手动最小化软件再点桌面）可能被当成显示桌面，此时瓦片会置顶在桌面上，但不影响软件使用；
- 更彻底的做法是 P6「真占格」：把瓦片窗口作为 WorkerW/Progman 的子窗口（类似 Rainmeter），天然在软件之下、显示桌面时可见，且不依赖轮询。当前版本先交付可用的近似方案。

## 5. v0.9.1 修复（2026-10-27 七次反馈）

反馈：**只能打开一次，第二次就打不开了**。

**根因**：v0.9.0 为了不让瓦片抢焦点，把瓦片窗口设成了 `focusable: false`。这个设置在浮层（会抢焦点）第一次关闭之后，会让瓦片窗口不再接收鼠标消息——窗口还在、`WindowFromPoint` 也命中它，但 `mousedown/click` 完全不触发（用主进程日志 + 真实鼠标点击复现：第 1 次能开，第 2、3 次连 mousedown 都没有）。

**修复**：

- 瓦片窗口改回 `focusable: true`；
- 启动时用 `showInactive()` 显示，避免启动瞬间抢焦点（这才是原本要解决的问题，用对 API 即可）；
- 去掉收浮层后的 `focusDesktop()` Alt 模拟（不必要的焦点操作，减少干扰）。

**验证**：真实鼠标连续点击瓦片 3 次 → **3/3 都能打开**（`scripts/e2e-reopen.js` 也作为回归脚本保留）。Win+D 后瓦片仍可见，切回软件后回到软件下面。

- 版本 0.9.1，重新打包 portable + zip。

## 6. v0.9.2 修复（2026-10-27 八次反馈）

反馈：浮层里**有的文件夹图标背景是黑色方块，有的是半透明**，希望统一半透明。

**根因**：Windows Shell 返回的文件夹缩略图格式不统一——部分文件夹（带照片预览的那些）返回的是**不带 alpha 的 RGB 位图**，背景是一整块纯黑；另一部分返回带透明通道的 RGBA。于是同一排图标里黑底和半透明混在一起。

**修复**：在 `icons.js` 里对**文件夹**缩略图做一次后处理：

- 检测缩略图边框是否几乎全是不透明纯黑；
- 是的话从四边向内做黑色像素**漫水填充**，只把与边界连通的纯黑背景抠成透明（文件夹内部的黑色预览内容不动）；
- 用 `nativeImage.createFromBitmap` 重新生成带 alpha 的图再缓存；
- 只对文件夹生效，图片/视频等真实黑色背景不受影响。

**验证**：14 个文件夹缩略图处理后四角 alpha 全为 0，截图 `shots/crop-folder-icons.png` 面板里所有文件夹都是半透明玻璃背景、无黑块；单测 13/13。

- 版本 0.9.2，重新打包 portable + zip。
