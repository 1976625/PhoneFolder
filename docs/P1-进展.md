三档背景的效果/耗时取舍：

| 模式 | 首帧 | 观感 | 备注 |
|---|---|---|---|
| wallpaper（默认） | 110ms | 深色毛玻璃，干净 | 不采集用户窗口；动态壁纸时是静态一帧 |
| capture | 121ms | 等同「模糊当前桌面」，会把窗口一起模糊 | 抓屏 1s 级，必须缓存预热 |
| acrylic | 79ms | 实时模糊但 Win11 浅色主题下奶白、发灰 | 只作实验开关保留 |

## 4. 关键踩坑与解法（都已修）

1. **无边框窗口被 Windows 夹到工作区。** 请求 1920×1080 的 `frame:false` 窗口，实际只给 1872×1080（少左侧 48px 任务栏），导致浮层右侧漏一条桌面、任务栏图标露出来。
   → 窗口隐藏时 `win.setBounds(display.bounds)` 铺满；已封装在 overlay/backdrop 创建处。
2. **`show()` 之后再 `setBounds` 会把 topmost 样式冲掉。** 表现为浮层被其他置顶窗口（如 Trae 浮标）盖住；Win32 枚举确认 `WS_EX_TOPMOST` 丢失。
   → 只允许「隐藏时 setBounds」，创建时 `alwaysOnTop:true`，打开时只 `show()`，不再改 bounds；`--hold` 调试模式可复现验证。
3. **面板居中偏右下。** `getBoundingClientRect()` 会算上上一次收起的 `transform: scale(0.19)`，量到缩小后的矩形再按它居中，导致二次打开位置漂移。
   → `centerPanel()` 先 `transform:'none'` 再测量。
4. **DWM acrylic 在浅色主题下发白。** 本机 App/System 都是浅色主题，acrylic 实测背景亮度 mean 70/对比度 std 10，像蒙了一层灰；改用壁纸模糊后 mean 23 / std 28，暗色玻璃质感才对。
   → 默认 `wallpaper`；`capture`/`acrylic` 留作开关。
5. **`desktopCapturer` 单次约 1s，不能进点击路径。** 原计划「打开时抓屏」会直接超时。
   → 启动 1.8s 后、瓦片 hover、浮层关闭后异步预热缓存；打开时只读缓存。
6. **透明 `+ thickFrame:false` 组合在 Electron 43 会崩进程**（诊断时复现）。已放弃该组合，改用不透明浮层，绕开透明窗渲染坑。
7. **环境变量 `ELECTRON_RUN_AS_NODE=1`**（DSH 终端自带）会让 Electron 以 Node 模式运行、窗口起不来；启动前需清除。

## 5. 与计划的偏差

| 计划 v0.2 | P1 实际 | 原因 |
|---|---|---|
| 背景默认 DWM acrylic | 默认 wallpaper，capture/acrylic 可选 | 浅色主题 acrylic 观感差；wallpaper 零延迟、无隐私画面 |
| 瓦片 84×84（含标签） | 窗口 84×104（84 卡片 + 文字标签外置） | 更像 iOS 文件夹；点击热区含标签 |
| 计划未含拖动/右键菜单 | 已加：拖动记忆位置、右键菜单（含临时退出） | 无托盘时没法退出；瓦片压图标时需要能挪 |
| 浮层 3×3 分页圆点 | 只有 1 页时隐藏圆点（9 项假数据） | 不误导用户 |
| P1 不含自动化视觉验证 | `pnpm shot` + `--hold` 截图自查 | 调动画/配色效率高 |
